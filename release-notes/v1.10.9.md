A small, focused release with one job: no internet outage, unreachable service, or dropped connection can end a running POTACAT session.

## 🛡️ Network failures can't crash the app anymore

An overnight session died because one of POTACAT's reporting connections (the FreeDV Reporter feed) couldn't reach its server — a plain connection timeout escalated into a full application crash. That whole class of failure is now closed, at two layers:

- The FreeDV Reporter client got the same hardening as every other network client: a connection attempt that dies late can't detonate after a reconnect has replaced it, and its errors are always handled.
- A process-wide safety net: any error that is purely a network failure (timeout, connection reset, unreachable host, DNS trouble) gets logged loudly and survived instead of ending the session. Real software bugs still surface exactly as before — this only covers the "the internet blinked" class.

If you run POTACAT unattended — overnight WSPR, a headless Pi, an idle-mode station — this is your release. Everything that decodes, logs, and keys keeps running through whatever your network does.
