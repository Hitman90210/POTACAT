Three fixes straight from this week's field reports — including the one that has quietly broken macOS auto-update since signing began.

## 🍎 macOS auto-update: fixed for real this time

A sharp-eyed user's ShipIt log found it: the bundled `rigctld` helper shipped **read-only** inside every signed Mac build, and macOS's updater refuses to install an update containing a read-only file — it silently relaunches your old version instead. That's the "clicked Restart, still on the old version" behavior, even with the app correctly installed in Applications.

Every file in the bundle now ships owner-writable, enforced at build time in two independent places so this class of bug can't come back.

**Mac users: one manual step to get here.** Because the bug lives in the update package itself, older versions can't auto-update *to* 1.10.7 — download this DMG, drag POTACAT.app into Applications over your old copy, and auto-update works from this version on.

## 📡 CW: a dead CW Key Port no longer silences your keying

If a CW Key Port was configured (Settings ▸ ECHOCAT ▸ Remote CW Keyer) but pointed at a port Windows can't open — a leftover COM assignment, or the same port your CAT connection already owns — every CW send since 1.10.5 quietly died waiting on it, even on rigs like the IC-7300 that key CW perfectly over CAT. A key port that doesn't come up now **falls back to normal CAT keying automatically**, with a log line telling you to fix or clear the stale setting. (FT-891/FT-710 keep the strict behavior — on those rigs CAT text keying transmits a dead carrier, so the key port remains authoritative.)

## 🏆 LoTW: big uploads no longer die mid-run

TQSL prints a several-line complaint for every QSO it skips, and a large log with many QSOs that don't match the chosen Station Location could overflow an internal buffer — POTACAT then cut TQSL off before anything uploaded, reporting a meaningless error. The buffer is now big enough for any real-world log: TQSL finishes, skips what doesn't match, uploads the rest, and the result line tells you exactly what happened.
